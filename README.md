Ответы на контрольные вопросы (10 штук):

1)Что такое Merge Conflict?
Это ситуация, когда Git не может автоматически объединить ветки, потому что в обеих были изменены одни и те же строки одного файла.

2)Почему в этой практике возник конфликт?
Мы изменили одну и ту же строку print("Hello") по-разному в ветке main и в ветке feature-message.

3)Почему важно создать обе ветки до изменения исходного файла?
Если создать ветку после изменения, она уже будет содержать новую версию файла, и конфликта при слиянии не возникнет (одна версия просто перезапишет другую).

4)Чем отличаются git fetch и git pull?
fetch только скачивает данные с сервера, но не применяет их к твоим файлам. pull скачивает и сразу сливает (merge) с твоим локальным кодом.

5)Для чего нужен Pull Request?
Это запрос на слияние твоих изменений в главную ветку. Он нужен для того, чтобы другие разработчики могли проверить код перед слиянием.

6)Почему мы объединили origin/main в feature-message, а не наоборот?
Потому что мы работаем локально в ветке feature-message и хотим сначала разрешить конфликт у себя, проверить, что всё работает, и только потом отправить в главную ветку.

7)Для чего используется окно Resolve Conflicts в PyCharm?
Для удобного визуального выбора того, какой код оставить (свой, чужой или оба) при конфликте.

8)Что такое итоговая версия файла (Result)?
Это файл, который получится после того, как ты вручную устранишь все противоречия.

9)Почему после разрешения конфликта нужно сделать коммит?
Потому что разрешение конфликта — это изменение файлов. Git должен зафиксировать это изменение в истории.

10)Для чего нужна команда git push после разрешения конфликта?
Чтобы отправить исправленный файл на GitHub, чтобы Pull Request увидел, что конфликт решен.
